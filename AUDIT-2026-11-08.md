## What is solid

- **Tenant isolation**: Postgres row-level security on 14 tables (enforced in Docker installs), a recursive query guard test, IDOR and cross-tenant sweeps over every parameterised route.
- **Least privilege in the database**: owner and runtime roles are separate; append-only audit log; deletions only through bounded functions.
- **Authentication**: MFA, refresh-token rotation, recent sign-in (10 min) for dangerous changes, Turnstile, per-account and per-address limits.
- **Ingestion**: every sensor/webhook is authenticated on the raw bytes before parsing (HMAC, constant time); idempotent alert ids; transactional outbox with retries and dead letters.
- **Autonomy is bounded**: manual by default; hybrid/automatic need an administrator, a written notice and a recent sign-in; only two live actions exist (block a public address, e-mail admins); critical and AI-proposed actions always wait for a person; hourly cap; emergency stop; keyed audit chain.
- **Integrations** (14 besides Wazuh): sealed secrets, egress pinned to vendor hosts, redirects refused, paging links to other hosts refused, errors scrubbed, no connector can respond.

## Findings

| # | Severity | Finding | Recommendation |
|---|---|---|---|
| A-1 | High (process) | **No real-provider verification.** Defender XDR, Azure, GCP, GuardDuty, Okta, GitHub, Slack, Teams, Jira, PagerDuty are tested only against simulated providers built from documentation. | One sandbox account per vendor; run each connector once and record the result before selling it. |
| A-2 | High (process) | **No soak, no independent penetration test, no high availability.** One API process, one database. | 14-day pilot soak, external pen test, second instance + managed Postgres with failover. |
| A-3 | ~~Medium~~ **Fixed** | `integration_connections` and `notification_outbox` were not under row-level security. | **Done (migration 0014):** both are under the same RLS policy as the other 14 tables. Workers reach other workspaces' due work only through bounded SECURITY DEFINER functions (claim, dead-letter, prune, metrics, GitHub lookup); everything a worker does with a row runs in that row's own workspace. Tests: `row-level-security.test.ts` (unscoped reads/writes confined, cross-workspace insert refused, functions return only what they are for); end-to-end on the built API with `DB_RLS=enforce` (protection modes, user journeys). |
| A-4 | Medium | **Poll worker throughput**: each instance claims at most 10 connections per 15 s and polls them one after another (120 s timeout each). With hundreds of cloud connections, polls fall behind. | Poll in parallel with a per-instance limit; expose "seconds behind" as a metric and alert on it. |
| A-5 | Medium | **Alert insert cost grows with connections**: every new alert runs extra queries per Slack/Teams/Jira/PagerDuty connection inside the same transaction. | Fine at current scale; at high volume, enqueue one fan-out job instead. |
| A-6 | Low | **Jira duplicate window**: the "already ticketed?" search can miss a ticket created seconds earlier (Jira index lag). | Store the created key before the outbox row is marked sent, or use an entity property lookup. |
| A-7 | Low | **Ticket links age out**: delivered integration messages are pruned after `NOTIFY_RETENTION_DAYS` (30), so the alert page stops showing the Jira link. | Keep the ticket key on the alert itself. |
| A-8 | Low | **Error scrubbing** removes only exact secret values ≥ 6 characters and known URL shapes. | Acceptable; keep provider error text short (already capped at 300 chars). |
| A-9 | Low | **Updates of vendor alerts are ignored**: a Microsoft/Azure/GCP/GuardDuty/Okta item is stored once by id; later severity changes do not reach Legion. | Store a revision and update the alert when the vendor's severity rises. |
| A-10 | Info | Response actions in identity/endpoint systems (disable account, isolate host) are simulation only. | Design, review and build one executor at a time, approval-only. |

No critical code defect was found.

## Verdict

- **Controlled pilot (one workspace, manual or hybrid mode):** ready, subject to the pilot checklist.
- **General production:** **not yet** — A-1 and A-2 must be closed first; A-4 before many customers (A-3 is fixed).
