## What is solid

- **Tenant isolation**: Postgres row-level security on 14 tables (enforced in Docker installs), a recursive query guard test, IDOR and cross-tenant sweeps over every parameterised route.
- **Least privilege in the database**: owner and runtime roles are separate; append-only audit log; deletions only through bounded functions.
- **Authentication**: MFA, refresh-token rotation, recent sign-in (10 min) for dangerous changes, Turnstile, per-account and per-address limits.
- **Ingestion**: every sensor/webhook is authenticated on the raw bytes before parsing (HMAC, constant time); idempotent alert ids; transactional outbox with retries and dead letters.
- **Autonomy is bounded**: manual by default; hybrid/automatic need an administrator, a written notice and a recent sign-in; only two live actions exist (block a public address, e-mail admins); critical and AI-proposed actions always wait for a person; hourly cap; emergency stop; keyed audit chain.
- **Integrations** (14 besides Wazuh): sealed secrets, egress pinned to vendor hosts, redirects refused, paging links to other hosts refused, errors scrubbed, no connector can respond.

## Findings

| # | Severity | Finding | Recommendation |
|---|---|---|---|
| A-1 | High (process) | **No real-provider verification.** Defender XDR, Azure, GCP, GuardDuty, Okta, GitHub, Slack, Teams, Jira, PagerDuty are tested only against simulated providers built from documentation. | One sandbox account per vendor; run each connector once and record the result before selling it. |
| A-2 | High (process) | **No soak, no independent penetration test, no high availability.** One API process, one database. | 14-day pilot soak, external pen test, second instance + managed Postgres with failover. |
| A-3 | ~~Medium~~ **Fixed** | `integration_connections` and `notification_outbox` were not under row-level security. | **Done (migration 0014):** both are under the same RLS policy as the other 14 tables. Workers reach other workspaces' due work only through bounded SECURITY DEFINER functions (claim, dead-letter, prune, metrics, GitHub lookup); everything a worker does with a row runs in that row's own workspace. Tests: `row-level-security.test.ts` (unscoped reads/writes confined, cross-workspace insert refused, functions return only what they are for); end-to-end on the built API with `DB_RLS=enforce` (protection modes, user journeys). |
| A-4 | ~~Medium~~ **Fixed** | Poll worker throughput: 10 connections per 15 s, polled one after another. | **Done (migration 0015):** connections are polled in parallel (`INTEGRATION_POLL_CONCURRENCY`, default 8, max 50 per instance); a full batch is followed at once by the next (up to 20 rounds per tick); the lease is computed to outlast the worst case of a batch. New metrics `legion_integration_poll_lag_seconds`, `legion_integration_connections_active`, `legion_integration_connections_error`, and two alerts (`LegionIntegrationPollsBehind` after 15 min over for 10 min; `LegionIntegrationStopped`), unit-tested with promtool. Test: 16 slow connections polled in under 2.5 s with at most 8 at once. Capacity per instance at the default: roughly 1 000 connections at a 5-minute interval. |
| A-5 | ~~Medium~~ **Fixed** | Alert insert cost grew with the number of connections (2 extra queries per Slack/Teams/Jira/PagerDuty connection, inside the alert transaction). | **Done:** `enqueueIntegrationMessages` now runs 3 queries however many connections exist (one read of connections, one grouped read of the hourly counts, one multi-row insert); behaviour is unchanged (per-connection hourly cap, dedupe per alert and connection). Test: 1 and 7 connections cost the same number of queries, each connection still gets its message once, a replay queues nothing. |
| A-6 | ~~Low~~ **Fixed** | Jira duplicate window: the "already ticketed?" search could miss a ticket created seconds earlier (Jira index lag). | **Done:** the new ticket key is written to the message the moment Jira returns it, and a retry reads that issue by key (not index-dependent). An attempt also records that it is about to create; if its answer was lost, a retry within 2 minutes waits instead of trusting an empty search. Tests: lost create answer is not repeated (two immediate retries, then found once the index catches up); a crash after creation reads the issue, no search. Remaining gap: a crash in the milliseconds between Jira answering and the key being saved is covered by the 2-minute wait, not eliminated by Jira itself. |
| A-7 | ~~Low~~ **Fixed** | Ticket links aged out: delivered integration messages are pruned after `NOTIFY_RETENTION_DAYS` (30), so the alert page stopped showing the Jira link. | **Done:** the ticket (connection, key, URL, time) is also written to the alert itself (`alerts.tickets`, one entry per connection, under the same row-level security), and the alert page reads it when the outbox row is gone. Test: the link is still shown after the delivered row is deleted; another workspace gets 404. Alerts delivered before this change keep their link only until their outbox row is pruned. |
| A-8 | ~~Low~~ **Fixed** | Error scrubbing removed only exact secret values ≥ 6 characters and known URL shapes. | **Done:** one scrubber (`integrations/scrub.ts`) for outbound and poll errors. It also removes each secret as base64, base64url, URL-encoded, JSON-escaped and as `a:b` pairs (a Basic header), the query string of any URL, chat/automation webhook URLs (Slack, Teams, Power Automate, PagerDuty), and everything the platform credential rules know (Bearer/Basic, JWT, cloud and vendor keys, `password=`, private keys, URL user:password). Poll errors were not scrubbed at all before. Secrets under 6 characters are still not matched literally (they would shred ordinary words). Tests: `tests/integration-scrub.test.ts` (in the mandatory security list). |
| A-9 | ~~Low~~ **Fixed** | Updates of vendor alerts were ignored: an item was stored once by id; later severity changes did not reach Legion. | **Done:** when a stored item comes again with a higher severity, the Legion alert is raised, a dated note is added, the change is audited (`alert.severity_raised_by_source`) and the alert's version is bumped so dashboards update. Never lowered; status never changed by a source. Pull connectors read by update time, so updates arrive. Test: `tests/integrations-edr-siem.test.ts`. |
| A-10 | Info | Response actions in identity/endpoint systems (disable account, isolate host) are simulation only. | Design, review and build one executor at a time, approval-only. |

No critical code defect was found.

## Verdict

- **Controlled pilot (one workspace, manual or hybrid mode):** ready, subject to the pilot checklist.
- **General production:** **not yet** — A-1 and A-2 must be closed first; A-3 to A-9 are fixed.
